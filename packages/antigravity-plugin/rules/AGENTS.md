# Hermes Swarm — Standing Rules

1. **1:1 Session-Bound Swarms & 3-Tier Topology**: Each Antigravity conversation owns exactly one swarm (`1 conversation = 1 swarm`, initialized via `swarm_manage(action="init")` with zero swarm switcher, `select`, or `archive`). **Primary** (User + Main Antigravity, `primary`) spawns **one** Tier-2 **Coordinator** subagent (`coordinator`) via `invoke_subagent` with **`Model="inherit"`** (fast/medium dispatcher — NEVER `pro`/XHigh for Coordinator; reserve `pro`/XHigh strictly for Tier-2 IDE Specialists), binds it with `swarm_manage(action="bind_coordinator")`, and handles only `@primary` escalations and final delivery. At Tier 2, the Coordinator acts strictly as a **thin dispatcher** (read only `Handoffs/current.md` and `hermes-swarm-pane/SKILL.md` once — never source files, skill manuals, or long logs inline): within 1–2 turns, Coordinator spawns **IDE frontier subagents** via `invoke_subagent(TypeName="self", Model="pro", ...)` for all thinking and judgment work (research, architecture/design, planning, specialist consultations, and adversarial verification), registers each spawned IDE subagent on the board via `swarm_manage(action="register_member", name=..., role=..., conversation_id="<exact conversationId>", assignment=...)` and instructs it to post its concise non-waking verdict directly via `swarm_board_post(swarm_id=..., sender="<name>", ...)` (without `@mention`ing peers or `@coordinator`) so the Board reflects real multi-agent traffic alongside `coordinator`, and runs `swarm_manage` + `swarm_worker` for Tier-2 Hermes **execution workers** (`worker|implementer|monitor|narrator`), which may spawn Tier-3 leaf subagents (`subagent`) via `delegate_task`. Clicking Antigravity members opens their native Antigravity conversation, whereas clicking Hermes workers opens the live read-only side-panel tab. **Deliverable boundary:** Swarm Board Overview is strictly an ops/coordination monitor (never a gallery for result images); workers/reviewers pass result images and artifacts to `@coordinator`, Coordinator verifies and hands them to `@primary`, and Primary delivers them to the user in chat.
2. **Dynamic Catalog & Local Role Policy**: Call `swarm_catalog()` before launching workers; choose `model`, `provider`, `reasoning`, or `profile` dynamically (or honor user-requested models and local `~/.config/hermes-swarm/role_policy.json` defaults returned by `swarm_manage(init|status)`). Never hardcode personal model names in shared docs/rules.
3. **Session & Workspace Isolation**: Scope every session strictly via `conversation_id` / `coordinator_conversation_id` and `swarm_workspace(action="get_workdir"|"set_workdir")`.
4. **Safe Parallelism & Overview**: Publish `swarm_manage(action="set_plan")` per `hermes-swarm-pane`, work in a normal repo (`worktree=False` default) with strictly disjoint file/directory assignments and `swarm_board_read(scope_action="claim"|"release")` `409` conflict locks (`worktree=True` and `prune_worktrees` only when explicitly requested), inspect diffs via `swarm_worker(action="diff")` / `swarm_workspace(action="git_diff")`. Reviewers/IDE verifiers report and execution authors fix—never let two workers edit the same file. `@<worker>` board posts steer running Hermes workers after their current tool call (persisted in tool history via `transform_tool_result`); to hard-abort an in-flight long remote command immediately or clear a looping worker, use `swarm_worker(action="kill", ...)` and spawn a replacement. On quota/capacity errors, use `swarm_worker(action="switch_model", ...)` and verify `status` to resume stalled work rather than killing and respawning.
5. **Reactive Waiting & Board Link**: Coordinator waits via `swarm_wait` (and sidecar wakeups); end the swarm-creation turn with `open_board` on its own line (never invent a manual board link or command). Read `hermes-swarm` before orchestrating a swarm.
6. **Project Vault Sync (Read & Write)**: When the active workspace declares an Obsidian project vault in its `AGENTS.md`, Primary resolves that vault path and passes it in the Coordinator brief. Coordinator MUST read the vault's `Handoffs/current.md` and `Lessons/lessons.md` before `set_plan`, and MUST write verified receipts/handoffs/one-line lessons back to that active project vault before posting `[done]` or escalating to `@primary` (keep `hermes-swarm` project-agnostic; never hardcode a vault path or divert dev/tooling handoffs to a separate personal vault).
7. **Full Transparency to the User (Primary IDE Agent / Primary)**: If you are the Primary Antigravity agent (`primary`), NEVER leave the user blind to what is happening in their project. Whenever you finish an audit, comparison, architecture design, multi-file rebuild, or bug-fix pass, lay out the full concrete breakdown directly in chat — every item, feature, gap, fix, tradeoff, and kept behavior in plain language — instead of hiding the substance behind a terse summary or pointing them to an external note to read themselves. Keep raw log dumps and noisy command spam in permanent notes/logs, never as a substitute for explaining the work clearly.
8. **Bounded Commands, Test Timeouts & Anti-Hang Discipline**: NEVER run unbounded tests, builds, servers, or background sweeps. Always enforce hard timeouts (Node `--test-timeout=30000`, Python/PowerShell `Wait-Job`/wall timeout `<= 90-120s`), kill hung child process trees immediately instead of waiting indefinitely, and NEVER let cleanup sweeps match `python*`/`node*` without excluding `os.getpid()` + ancestor PIDs and strictly matching the target `worktree_path`/`swarm_id`/`task_id`. Coordinators must inspect logs and kill/replace any worker stuck silently on a process/test instead of parking.
9. **Thin Coordinator + Engineers vs. Bricklayers Split & Hub-and-Spoke Addressing**: Primary MUST spawn Coordinator with `Model="inherit"` (fast/medium dispatcher); Coordinator reads ONLY the vault's `Handoffs/current.md` and `hermes-swarm-pane/SKILL.md` once (zero deep file/log/skill reading inline) and immediately delegates ALL thinking and judgment roles (Research, Architecture/Design, Planning, Specialist Consultations, and Adversarial Verification) to Tier-2 IDE frontier subagents (`invoke_subagent`, `TypeName="self"`, `Model="pro"`, read-only prompt constraint for research/review). Reserve Hermes `swarm_worker` processes strictly as execution bricklayers (`worker` / `implementer`, `monitor`, `narrator` using `role_policy` defaults or `swarm_catalog()` selections) for implementing pre-designed specs, running builds, SSH loops, profiling, test suites, and git/CI mechanics. Respect local `~/.config/hermes-swarm/role_policy.json` (which can enforce `"reject"` on IDE-only roles in `swarm_worker`). Because `wakeup_bridge` only wakes `primary` and `coordinator`, Hermes workers must **only `@coordinator`** on the board (never direct to separate IDE subagents), and Coordinators pass compact subsystem briefs and bridge results between IDE subagents and Hermes workers.
